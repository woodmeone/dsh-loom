# ADR-0002：只保留两个注入位

- 状态：已接受
- 日期：2026-10-18

## 背景

注入位置有三种现成设计可参考。

**酒馆预设**用两个字段表达位置，其实是两种模式：

| 字段 | 含义 |
|---|---|
| `injection_position: 0` + `injection_depth: N` | 相对位置：距末尾第 N 条 |
| `injection_position: 1` + `injection_order` | 绝对位置：钉在系统段，按 order 排 |

**dsh-prompt-hub 原型**（已弃用）设计了四个位置：`P1 = -100000`、`P2 = 500`、`P3 = 10100`、`P4 = messages.length`。

**注意力实测**是 U 型：两头高、中间塌。所以「位置」对模型的唯一意义是**落点在曲线上的哪一段**，而这个曲线只有两个值得拧的峰。

## 决策与取舍

**只保留两个位置：顶部一个段落、尾部一条消息。块在位置内按序叠加。**

```
顶部（top）   一个段落，order = -100000
尾部（tail）  一条消息，追加在消息数组末尾
```

放弃了：

- **P2 / P3 两个中间位。** 落在谷底，投入产出不成比例。
- **把 `depth` 做成第三个位置维度。** `depth 4` 与 `depth 6` 的差别小于换一个词。

`tailDepth` 字段**保留但不对它做排布**——它只为让导入的酒馆预设信息不丢失而存在。导入时 `injection_depth` 原样装进字段，位置一律归到尾部。

## 后果

- 顶部只有一个段落 → 上游 `-100000` 的坑位冲突**自动消失**。
- 缓存的静态前缀更稳：动的是尾部，顶部整块不动。
- **以后想把单个块单独挪到消息中间，不再可能。** 要加就得改这条决策。
- 导入酒馆预设时，`injection_position: 0 / depth: 4` 这类槽位会**丢掉深度信息**，全部落在尾部并按预设顺序排列。预设的**相对顺序**保住了，**绝对深度**没保住。
- `depth` 这个词在本项目里只剩数据含义，不承载任何行为。
